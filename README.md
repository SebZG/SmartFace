# SmartFace

SmartFace is a full-stack face detection application. Create an account, sign in, paste an image URL, and the browser detects faces in the image and draws bounding boxes around them. Each successful detection increments the signed-in user's entry count.

## Features

- User registration and sign-in
- Password hashing with bcrypt
- PostgreSQL-backed user profiles and detection counts
- Client-side face detection with TensorFlow.js and MediaPipe
- Responsive React interface with animated particle background

## Project structure

```text
.
├── Back-End/    Express API and PostgreSQL access
└── Front-End/   React/Vite client application
```

## Prerequisites

- Node.js and npm
- A PostgreSQL database

The backend expects these PostgreSQL tables:

- `login(email, hash)`
- `users(id, name, email, entries, joined)`

`users.id` should be generated by the database, and `users.entries` should default to `0`.
The repository does not include database migrations, so create these tables before starting the API.

## Local setup

1. Install dependencies in both applications:

   ```bash
   cd Back-End
   npm install

   cd ../Front-End
   npm install
   ```

2. Create `Back-End/.env`:

   ```dotenv
   API_PORT=3000
   DB_HOST=localhost
   DB_PORT=5432
   DB_USER=your-postgres-user
   DB_PASSWORD=your-postgres-password
   DB_NAME=smartface
   ```

3. Create `Front-End/.env` and point it to the API:

   ```dotenv
   VITE_API_URL=http://localhost:3000
   ```

4. Start the backend:

   ```bash
   cd Back-End
   npm start
   ```

5. In another terminal, start the frontend:

   ```bash
   cd Front-End
   npm run dev
   ```

   Open the local URL printed by Vite.

## API

The backend exposes the following routes:

| Method | Route | Description |
| --- | --- | --- |
| `GET` | `/` | Health check |
| `POST` | `/register` | Create a user |
| `POST` | `/signin` | Authenticate a user |
| `GET` | `/profile/:id` | Retrieve a user profile |
| `PUT` | `/image` | Increment a user's detection count |

The frontend uses `VITE_API_URL` as the API base URL. Images are processed in the browser, so the supplied image host must allow the browser to load the image for canvas-based detection.

## Deployment

The frontend and backend can be deployed as separate services. Configure the backend PostgreSQL and port variables in the hosting provider, then set the frontend's `VITE_API_URL` to the deployed API URL before building the frontend.
